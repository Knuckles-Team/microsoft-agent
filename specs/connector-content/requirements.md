| `CONN-MICROSOFT-AGENT-CONNECTOR-CONTENT-R002` | **Destructive operations use the SDK's one declaration and guard.** Every destructive operation (deletes, removals, wipes, retirements, application passwords, service principals, role assignments, conditional access, organization and admin SharePoint updates, risky-user dismissal, immediate Intune reboot and shutdown, desktop-flow cancellation, PowerPoint slide deletion, and destructive Windows companion actions) is declared with the SDK (`destructive_operation` on the Graph client methods, `guard_destructive` in the hand-written tools; `SCION-CONNECTOR-CONTROL-R930`, provider). Each served tool carries the MCP `destructiveHint` and the standard `confirm` argument, and a call without a live confirmation, `confirm`, or the operator setting `SCION_ALLOW_DESTRUCTIVE` makes no request. The connector defines no `MICROSOFT_ALLOW_DESTRUCTIVE` setting and no acknowledgement field in the Intune confirmation evidence; the gateway decides approval (`ARBORA-FLEET-R015.6`, consumer). `MICROSOFT_ALLOW_WRITES` stays as deployment access scope. Caller chain: `microsoft-mcp` runs `scion_sdk.cli:serve` to `microsoft_agent/mcp_server.py`, which serves the Graph client methods through `register_tool_surface` and the hand-written tools of `integration_tools.py` and `office_bridge.py`. Shape: `@destructive_operation` on eleven methods in `microsoft_agent/api/`; `guard_destructive` in five hand-written tools; `tool_policy.py` keeps only the access-scope tier. Proving test: `tests/test_destructive_declaration.py::test_destructive_tools_are_declared_and_take_confirm`. |
